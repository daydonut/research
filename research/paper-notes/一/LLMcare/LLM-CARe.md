# LLM-CARe 如何生成高质量合成电子病历

**CRITIC–ADVISER–REVISER CYCLIC REFINEMENT: TOWARDS HIGH-QUALITY EMR CORPUS GENERATION WITH LLMS**

> **论文**：Chen Ning 等，*Critic–Adviser–Reviser Cyclic Refinement: Towards High-Quality EMR Corpus Generation with LLMs*，ICLR 2026。  
> **关键词**：合成电子病历（EMR）、临床质量约束、分层迭代、多智能体、隐私与数据效用。  
> **一句话结论**：论文将“生成像病历的文本”改写为“按语料、字段、文档三个层次检查并修复临床质量”，在不使用真实病历文本进行生成模型训练或示例提示的设置下，提高了合成病历的质量及其训练下游模型的效用。

## 1. 研究问题：像病历，不等于好病历

真实 EMR 难以共享，因为它包含敏感的患者与机构信息。合成 EMR 可以缓解数据获取难题，但仅仅模仿真实记录，可能同时继承记录中的遗漏、错误和偏倚；让 LLM 直接生成，又容易得到过于典型、概念覆盖不足的病例。

论文真正要解决的问题是：**如何在不让生成模型接触真实病历原文的前提下，生成分布合理、字段完整、医学正确、前后一致，而且能用于训练临床任务模型的 EMR 语料？**

![论文图 1：传统合成 EMR 方法与 LLM-CARe 的问题设定](images/figure1_problem_vs_care.png)

*图 1（原论文第 2 页）：传统方法偏重模仿或直接生成，LLM-CARe 则引入参考分布、临床规则和逐轮质量检查。*

一个具体的错误是论文表 5 中的“诊断为子宫平滑肌瘤，性别为男”。文本形式可以完整，医学事实却不成立。另一类错误是主诉写“腹泻 2 天”，现病史却否认腹泻。这些问题需要显式检查，而不能只用文本流畅度衡量。

## 2. 已有方法的缺口

| 方法 | 主要做法 | 本文关注的缺口 |
| --- | --- | --- |
| LSTM、GAN 等 | 学习真实记录的结构和分布 | 缺少显式的临床完整性、正确性与一致性约束 |
|  |  |  |
| LLM Direct | 在一个提示中要求生成完整病历 | 多种约束竞争，容易遗漏字段或产生分布偏差 |
| Self-Refine | 整体批评、整体修改 | 未区分语料分布、单字段内容和跨字段逻辑 |

**关键判断**：已有方法并非完全不能生成合理病历，而是没有在同一流程中系统处理**多层级质量约束、生成时不依赖真实病历文本、下游可用性**三个目标。

## 3. 方法：把质量约束拆成三级闭环

LLM-CARe 先按目标诊断生成初始草稿，再依次执行 **Corpus → Section → Document** 三个阶段。每个阶段内部都循环执行：

```text
Critic：指出当前违反了哪项质量标准
   ↓
Adviser：给出针对性的修改建议
   ↓
Reviser：修改选中的病历或字段
   ↺ 再次检查
```

![论文图 3：LLM-CARe 的三级 Critic–Adviser–Reviser 框架](images/figure3_llm_care_framework.png)

*图 2（原论文图 3，第 3 页）：同一循环在三个层次检查不同的问题。论文设置为每阶段两轮；更多轮次带来的质量收益很小。*

### 3.1 Corpus：检查整批病历是否合理

- **人口学典型性**：年龄、性别分布是否接近目标人群。
- **知识覆盖度**：症状、检查、化验、手术、药物等临床概念是否得到足够覆盖。
- **操作方式**：Critic 根据真实训练集的**汇总统计**计算分布差异，Adviser 找出值得调整的记录，Reviser 修改这些记录。

例如，1 万份病历中 95% 都是老年男性，即使每份记录单独看没有错误，整批语料仍不适合代表目标人群。


### 3.2 Section：检查每个字段是否完整

EMR 被拆成：
- 性别；
- 年龄；
- 主要诊断；
- 主诉；
- 现病史；
- 住院过程；
- 出院医嘱。
然后逐字段检查完整性。例如：
- 主诉是否说明就诊原因？
- 主诉是否包含起病时间？
- 现病史是否描述起病急缓？
- 现病史是否列出主要症状？
- 住院过程是否包含检查和治疗？
- 出院医嘱是否包含具体药物剂量和用法？
这一步把“病历质量”转化成多个可以回答 Yes/No 的检查项，降低了 Critic 的判断难度。

按性别、年龄、主要诊断、主诉、现病史、住院过程、出院医嘱等字段，逐项判断内容是否满足要求。例如，主诉是否交代就诊原因和起病时间；住院过程是否记录检查与治疗；出院医嘱是否写明药物、剂量和用法。未满足的项目再由 Adviser 指定补充内容，Reviser 局部修改。

### 3.3 Document：检查整份病历是否说得通

在完整记录上检查**医学正确性**和**上下文一致性**：诊断与性别是否相容，主诉与现病史是否矛盾，症状、检查、治疗和出院医嘱是否相互支持。此阶段修复跨章节冲突，而不只是把单个字段写得更长。

**为何按这个顺序？** 语料分布对齐是相对柔性的调整；字段补全可能引入新信息；最后再施加最严格的整份文档逻辑约束，可减少后续修改破坏已完成的内部一致性。（论文第 5 页，§3.4）

## 4. 实验设计：质量评估 + 下游任务

- **数据**：192k 份去标识化 EMR，覆盖 302 种疾病；按疾病分层进行 8:2 划分。各方法按同样的疾病分布生成相同数量的合成记录。
- **生成与评估**：LLM 方法使用 Qwen2.5-7B-Instruct；质量判断使用 Qwen2.5-32B-Instruct。字段完整性、医学正确性、上下文一致性由 LLM 按明确标准评估；人口学典型性与知识覆盖度由统计比较评估。
- **下游效用**：用合成 EMR 微调 Qwen2.5-0.5B-Instruct，在真实 EMR 测试集上完成诊断预测、检查推荐、治疗推荐。任务被构造成多项选择题，输入主要是主诉与现病史；因此结果表示该实验设置下的预测准确率，并非实际临床决策效果。（论文第 5–6 页，§4）

## 5. 主要结果

### 5.1 五项 EMR 质量指标

| 方法 | 完整性 | 医学正确性 | 上下文一致性 | 人口学典型性 | 知识覆盖度 |
| --- | ---: | ---: | ---: | ---: | ---: |
| LLM Direct | 77.1 | 90.7 | 87.9 | 77.7 | 73.9 |
| Self-Refine | 78.3 | 90.9 | 88.5 | 77.7 | 78.0 |
| MedSyn | 84.8 | 95.3 | 91.9 | 84.1 | 84.5 |
| **LLM-CARe** | **91.2** | **98.6** | **93.8** | **96.8** | **94.1** |

*数据来源：论文表 1，第 7 页；单位为百分比，表内省略三次不同随机种子实验的标准差。*

相较于 LLM Direct，提升最大的是知识覆盖度 **+20.2 个百分点**、人口学典型性 **+19.1 个百分点**和内容完整性 **+14.1 个百分点**。这说明收益并不只体现在文字润色，而是体现在整批数据的组成和各字段的临床信息量。

### 5.2 合成数据能否训练有用的模型？

| 任务（micro accuracy） | LLM Direct | MedSyn | LLM-CARe | 相对 LLM Direct |
| --- | ---: | ---: | ---: | ---: |
| 诊断预测 | 81.8 | 81.7 | **82.6** | +0.8 |
| 检查推荐 | 64.4 | 82.9 | **85.3** | +20.9 |
| 治疗推荐 | 60.9 | 74.5 | **76.9** | +16.0 |

*数据来源：论文表 2，第 7 页；单位为百分比。*

诊断预测的增益较小；检查和治疗推荐的增益明显。论文的解释是：直接生成已能覆盖较常见的“症状→诊断”模式，但检查、操作、药物等概念更依赖广泛的知识覆盖。相对较强的 MedSyn，LLM-CARe 在检查和治疗推荐上各提高 **2.4 个百分点**。

![论文图 7：各阶段 EMR 质量与下游任务表现的变化](images/figure7_stage_trends.png)

*图 3（原论文图 7，第 8 页）：语料阶段主要改善分布与概念覆盖，并带来检查、治疗推荐的大幅提升；字段和文档阶段继续改善完整性、正确性与诊断任务。*

## 6. 哪些证据支持方法有效？

1. **逐阶段变化符合设计目标**：各质量维度在对应阶段改善最明显；最终五项指标均高于直接生成。（图 7）
2. **消融实验支持三个角色各有作用**：去掉 Critic、Adviser 或 Reviser，质量和下游表现均下降。（图 8）
3. **不只对单一基础模型有效**：换用 LLaMA 3.1、Meditron 3 和 R1-Distill-Llama，分层修订仍优于直接生成。（表 3）
4. **增加真实病例示例没有明显收益**：在初稿生成时加入真实 EMR 示例的变体，与原方法表现接近。（图 9）
5. **有外部和人工评估**：在 MIMIC-IV-Note 的诊断预测实验中仍领先；四位临床医生评估 200 份合成记录，医生与 LLM 评估的总体 Cohen’s κ 为 **0.833**。（附录 J、表 4）

## 7. 创新点与边界

**真正的创新**是把模糊的“高质量病历”拆成可检查的规则，再把不同粒度的规则分配给不同阶段；Critic 负责发现问题，Adviser 负责给出具体操作，Reviser 负责局部修复。它不是单纯把更多要求塞进一次提示，也不是仅靠更强的基础模型。

需要保留以下边界：

- **隐私是相对结论**：生成时不使用真实 EMR 原文，但仍使用真实数据的疾病标签、年龄与性别分布以及临床实体频率等汇总信息。论文的成员推断攻击准确率为 MedSyn **0.533**、LLM-CARe **0.504**（0.5 约为随机猜测）；这支持该攻击设置下风险较低，不能证明完全没有隐私风险。（附录 I，表 11）
- **规则满足不等于事实验证**：Reviser 为补齐字段而生成的细节可能临床合理，却不对应某个真实患者。合成数据质量分数不能直接解释为患者事实被证实。
- **覆盖范围有限**：论文主要研究一次住院 episode 的多字段文本；跨多次就诊的纵向一致性、药物相互作用、复杂数值约束、罕见表现及跨医院文书风格尚未得到充分验证。
- **计算成本更高**：生成 38k 份 EMR，单张 RTX 4090 上直接生成约 **13 小时**，LLM-CARe 约 **36 小时**，约为 **2.8 倍**。（附录 M）



## 汇报收束

**LLM-CARe 的贡献，是把 EMR 合成从“单次模仿文本”变成“按临床质量原则进行分层、可检查、可迭代的修订”。** 它最明显地改善了数据集分布、临床概念覆盖和字段完整性，并让合成数据在真实测试集上的检查、治疗推荐任务更有用；代价是更多推理计算，以及对人工制定规则的持续依赖。
